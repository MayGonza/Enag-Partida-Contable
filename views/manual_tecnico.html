1. Arquitectura General del Sistema

El Sistema Integral de Gestión Administrativa de la ENAG está fundamentado en un modelo Jamstack / Serverless desacoplado, diseñado para garantizar alta velocidad, cero costo fijo de infraestructura de servidores y máxima seguridad institucional.

Patrón Arquitectónico: Frontend modular desacoplado en cliente (HTML5/Vanilla CSS/ES6+) comunicándose directamente mediante protocolos seguros HTTPS y WebSocket con Google Firebase (Firebase Authentication y Cloud Firestore NoSQL). 
┌────────────────────────────────────────────────────────┐
│                   CLIENTE / NAVEGADOR                  │
│                                                        │
│   • HTML5 Semántico + CSS Variables (:root)            │
│   • Lógica en JavaScript ES6+ (Async/Await nativo)     │
│   • Generación Client-Side de PDF (jsPDF + AutoTable)  │
│   • Parseo de Libros Excel en Navegador (SheetJS)      │
└───────────────────────────┬────────────────────────────┘
                            │ HTTPS / WebSockets WSS
                            ▼
┌────────────────────────────────────────────────────────┐
│               GOOGLE FIREBASE SERVICES                 │
│                                                        │
│   • Firebase Hosting: Red CDN global con SSL y caché   │
│   • Firebase Authentication: Usuarios y email verif.   │
│   • Cloud Firestore: Almacén NoSQL y sync tiempo real  │
└────────────────────────────────────────────────────────┘

4. Esquema de Base de Datos (Cloud Firestore)

Las colecciones principales almacenadas en Firestore son:

4.1. Colección usuarios

Documentos ubicados en /usuarios/{uid}:

  • uid (string): ID único de usuario en Firebase Auth.
  • nombre (string): Nombre completo del colaborador.
  • usuario (string): Nombre de usuario institucional.
  • email (string): Correo corporativo autenticado.
  • departamento (string): Contabilidad, RRHH, Producción, Comercialización, TI.
  • sessionId (string): UUID de la sesión activa para prevención de concurrencia.
  • lastLogin (timestamp): Registro del último acceso.

4.2. Colección cotizaciones

Documentos ubicados en /cotizaciones/{numero}:

  • numero (number): Folio numérico único correlativo.
  • fecha (string): Fecha y hora en formato ISO.
  • cliente (map): { nombre, rtn, contacto, telefono, direccion, correo }.
  • items (array): [{ producto, descripcion, cantidad, precioUnitario, impuesto, precioTotal }].
  • totalBase, valorDescuento, totalNeto, totalImpuesto, totalGeneral (numbers).
  • estado (string): 'Pendiente', 'Aprobada', 'Rechazada'.
  • timestamp (timestamp): Marca temporal del servidor.

4.3. Colección bitacora

Registro histórico inmutable de auditoría institucional:

  • modulo (string): Área de origen del evento.
  • accion (string): Crear, Modificar, Eliminar, Generar PDF, etc.
  • mensaje (string): Detalle textual legible.
  • usuario (string): Operador responsable.
  • timestamp (timestamp): Fecha y hora exacta registrada en servidor.

5. Seguridad y Reglas de Firestore

Las reglas en firestore.rules bloquean accesos anónimos y restringen permisos por verificación de email:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    function isAuth() {
      return request.auth != null && request.auth.token.email_verified == true;
    }
    
    match /usuarios/{userId} {
      allow read: if isAuth();
      allow write: if isAuth() && (request.auth.uid == userId || request.auth.token.admin == true);
    }
    
    match /cotizaciones/{document=**} {
      allow read, create, update, delete: if isAuth();
    }
    
    match /bitacora/{logId} {
      allow read, create: if isAuth();
      allow update, delete: if false; // Inmutabilidad garantizada
    }
  }
}

6. Control de Sesión Única (Concurrencia)

Para garantizar que las credenciales no sean compartidas simultáneamente:

  1. Al autenticarse en views/login.html, el cliente genera un identificador aleatorio de sesión (sessionId = crypto.randomUUID()).
  2. Se almacena en localStorage y se actualiza en el documento /usuarios/{uid} en Firestore.
  3. Un listener onSnapshot monitorea el documento en tiempo real. Si detecta que doc.data().sessionId !== localStorage.getItem('enag_session_id'), bloquea la interfaz de inmediato y ejecuta firebase.auth().signOut().

7. Algoritmos y Fórmulas Clave

7.1. Cotizaciones y Descuentos Oficiales

Cada ítem calcula su total bruto y descuenta el porcentaje de ley (ej. 25% Adulto Mayor, 60% Municipalidades). Los impuestos (ISV 15%) se aplican sobre el subtotal neto únicamente a ítems gravados (no exentos).

⚠️ Regla de Desarrollo: Cualquier función que use await window.enagConfirm(...) o interacción asíncrona DEBE declararse explícitamente con async function para evitar errores de sintaxis en tiempo de análisis.

7.2. Balanceo de Partidas Contables

La partida doble exige Math.abs(totalDebe - totalHaber) < 0.001. Si existe diferencia, la UI bloquea el guardado y la exportación de PDF, informando el valor exacto del descuadre.

7.3. Subsidios IHSS (Metodología ENAG)

Sueldo Diario de Referencia: (Techo IHSS * 3) / Días_3_Meses_Anteriores. El 66% es subsidio IHSS reintegrable a la ENAG; el 34% es aporte patronal complementario.

9. Procedimiento de Despliegue en Firebase

El despliegue a producción se realiza mediante Firebase CLI:

# 1. Iniciar sesión en Firebase (si no se ha hecho previamente)
npx firebase login

# 2. Desplegar reglas de Firestore
npx firebase deploy --only firestore:rules

# 3. Desplegar la aplicación web a Firebase Hosting
npx firebase deploy --only hosting
URL de Producción: https://sistemagestionenag.web.app

10. Resolución de Incidencias Comunes

Error / Incidencia Causa Técnica Solución
SyntaxError: await is only valid in async functions Uso de await en función declarada de manera síncrona. Agregar la palabra reservada async a la función.
Uncaught ReferenceError: agregarFila is not defined El script falló en tiempo de parseo por un error previo de sintaxis. Revisar la consola del navegador y corregir el primer error de sintaxis en el archivo.
Missing or insufficient permissions El usuario no ha verificado su correo electrónico en Firebase Auth. Abrir el enlace de verificación enviado al correo del usuario.
